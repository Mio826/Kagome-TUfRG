============================================================
4. SAFE REBUILD PROCEDURE
============================================================

First load Anaconda and leave the damaged environment:

module load anaconda3
conda deactivate 2>/dev/null || true

Define the normal environment path:

ENV="/storage/scratch1/4/mli826/conda_envs/diverge-test"

Before rebuilding, rename the damaged environment as a temporary backup:

OLD="/storage/scratch1/4/mli826/conda_envs/diverge-test-broken-$(date +%Y%m%d)"

mv "$ENV" "$OLD"

Do NOT immediately delete the broken backup.

Now recreate a clean environment at THE SAME ORIGINAL PATH:

module load anaconda3

ENV="/storage/scratch1/4/mli826/conda_envs/diverge-test"

mkdir -p /storage/scratch1/4/mli826/conda_envs

conda create \
  -p "$ENV" \
  python=3.10.20 \
  pip \
  -y

Activate it:

conda activate "$ENV"

unset PYTHONHOME
unset PYTHONPATH

Check:

echo "CONDA_PREFIX=$CONDA_PREFIX"
which python
python --version
python -m pip --version

The Python executable must be:

/storage/scratch1/4/mli826/conda_envs/diverge-test/bin/python

export MKL_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export NUMEXPR_NUM_THREADS=1

PYTHONNOUSERSITE=1 is recommended because it prevents the job from
silently loading packages from:

~/.local/lib/python3.10/site-packages

instead of the intended conda environment.

============================================================

The conda environment and large FRG numerical outputs currently live on
PACE scratch because non-scratch storage is insufficient.

Therefore the conda environment should be treated as disposable and
rebuildable.

The durable/reproducible pieces are:

- TUfRG Python source code
- sbatch scripts
- this environment rebuild instruction
- conda package manifest
- pip package manifest
- important final numerical results backed up elsewhere when necessary

If scratch damages the environment again, rebuild it from this file rather
than trying to repair many partially deleted packages.
