divERGe original-code audit summary for explicit-spin kagome TUFRG
=====================================================================

Purpose
-------
We inspected the original divERGe source and examples to understand why the
explicit-spin, no-SOC kagome model did not reproduce the PRR/SU2-reduced
benchmark hierarchy.

The benchmark requirement is:
  U-only       -> Gamma magnetic / FM-like
  V-only       -> Gamma singlet SC / onsite-A1-like
  mixed U,V    -> finite-M charge/magnetic sectors become competitive

Main findings
-------------

1. Explicit-spin postprocess must use raw unprojected channels:
   tu_channel_calc_project = 0

   Source evidence:
   In src/tu/postproduction.c, when channel_calc_project != 0, the saved channel
   decomposition uses vertex->projection_helper rather than raw Pch/Cch/Dch.
   P_projection, C_projection, and D_projection are explicitly called.  For
   channel_calc_project < 0, C is also multiplied by -1.  For SU2=0, the D
   branch still calls D_projection.

   Consequence:
   Our explicit-spin diagnosis constructs physical PH sectors from raw
   Pchannel/Cchannel/Dchannel, especially K_ph = D - C followed by Pauli
   projection.  This is only meaningful if saved P/C/D are raw unprojected
   channel tensors.  Therefore tu_channel_calc_project=-1 corrupts the
   explicit-spin diagnosis.

   Required project change:
   In explicit-spin runs, set --tu-channel-calc-project 0.
   Add a hard guard in TUfRG_instability.py:
       if SU2 == 0 and tu_channel_calc_project != 0:
           raise RuntimeError(...)

2. The interaction vertex should follow divERGe's official D-channel s1=-1
   convention, not manual spin enumeration.

   Source evidence:
   The documentation says rs_vertex_t orbital/spin configuration is
   channel-specific, and s1=-1 auto-generates all SU(2)-related components for
   models where SU(2) is broken in the kinetic part.  In
   init_interaction_channels.c, the s1=-1 expansion is channel-dependent:
     D channel: (s1,s2,s3,s4) = (si1,si1,si2,si2)
     C/P channel: (s1,s2,s3,s4) = (si1,si2,si1,si2)

   Official examples:
   trigKaneMele.c, square_lat_rashba.c, triangular_lat_rashba.c, and kagome.cpp
   use explicit spin, SU2=0, and density interactions written as
       chan='D', s1=-1
   rather than manual enumeration.

   Consequence:
   The current TUfRG_model.py manual density_vertices() uses
       (s1,s2,s3,s4) = (s_left,s_right,s_left,s_right)
   for D-channel density interactions.  This does not match the official
   D-channel s1=-1 expansion.  It is very likely a second major reason the
   no-SOC explicit-spin bridge test failed.

   Required project change:
   Add an official-style vertex builder, e.g.
       density_vertices_official_s1minus1(...)
   and make it the default for spinful production:
       onsite U: one D-channel vertex per onsite orbital, s1=-1
       NN V: one D-channel vertex per directed NN bond, s1=-1

   Keep the old manual builder only for debugging/comparison until the bridge
   test is complete.

3. Do not use raw Pvec/Cvec/Dvec to decide instabilities.

   Source evidence:
   postproduction.c saves leading decompositions of the channel matrices
   themselves.  These are not multiplied by loops.  Linearized-gap quantities,
   by contrast, multiply projected channels by pp_bubble_int or ph_bubble_int
   before SVD.

   Consequence:
   Our Level-1 diagnosis principle is correct:
       compare singular values of K(q) @ L(q)
   not raw channel eigenvectors.

4. Built-in S_sc/S_mag/S_charge are only q=0 cross-checks.

   Source evidence:
   lingap_ff() is documented in source as only calculating q=0 linearized gap.
   It multiplies projection_helper with pp_bubble_int or ph_bubble_int and then
   performs SVD.

   Consequence:
   Built-in S_* can cross-check Gamma FM/SC behavior, but cannot diagnose M-point
   CDW/SDW/CBO/SBO.  M-point diagnosis must use q-resolved Pchannel/Cchannel/
   Dchannel and pploop/phloop.

5. Output axis ordering is now confirmed.

   util/output.py reshapes channel and loop arrays as:
       (n_spin*n_spin, n_orbff, n_spin*n_spin, n_orbff, nk)
   for Pchannel, Cchannel, Dchannel, pploop, and phloop.

   A TU propagator test also writes the loop order as:
       (s1,s2,m1 ; s3,s4,m2 ; q)
   flattened compatibly with this shape.

   Consequence:
   The Level-1 K(q) @ L(q) construction using these arrays is structurally
   justified, provided the channel tensors are unprojected.

6. PP sign should not import old N-patch signed-eigenvalue logic.

   Source evidence:
   divERGe flow internally has its own diagrammatic factors.  The postprocess
   linearized-gap solver uses SVD and returns nonnegative singular values.

   Consequence:
   For divERGe TU output, use:
       SC strength = sigma_max(P(q) @ L_pp(q))
   Do not manually flip P or search for “most negative eigenvalue” unless doing
   a separate debug comparison.

7. Hopping convention is basically understood.

   ham_at_k.c shows hopping contributes as:
       H[s1,o1; s2,o2] += exp(-i R.k) * t
   and s1=-1 in hopping expands spin-independently in non-SU2 models.

   Consequence:
   The hopping/SOC side is not the current primary suspect.  Keep the existing
   hopping sanity checks, but the source-level convention is not the major issue.

Recommended code changes
------------------------

TUfRG_runner.py
  - Change argparse default:
        --tu-channel-calc-project default -1  ->  0
  - Update help text to say explicit-spin raw diagnosis requires 0.
  - Optionally warn when explicit-spin SU2=0 is combined with nonzero
    tu_channel_calc_project.
  - In sbatch scripts, explicitly pass --tu-channel-calc-project 0.

TUfRG_model.py
  - Add official-style density vertex builder:
        density_vertices_official_s1minus1(U,V,...)
  - Use D-channel vertices with s1=-1:
        ("D", R, o1, o2, -1, 0, 0, 0, (V,0))
    following official examples.
  - Make this the default in build_model, or add a CLI/model option:
        vertex_convention = "official_s1minus1" | "manual"
    For production, default should be official_s1minus1.
  - Update metadata to record vertex_convention.
  - Keep the old density_vertices() as density_vertices_manual() for comparison.

TUfRG_instability.py
  - Add a hard error:
        if data.SU2 == 0 and data.tu_project != 0:
            raise RuntimeError("Explicit-spin diagnosis requires unprojected P/C/D channels: tu_channel_calc_project=0")
  - Check PP code for any extra Kpp=-P or old signed eigenvalue convention.
    If present, remove it. Use SVD of P @ pploop.
  - Keep PH explicit-spin construction K_ph=D-C + crossed Pauli projection as
    a working calibrated convention, but revalidate after fixing runner/model.

TUfRG_formfactor_from_modes.py
  - No urgent structural change.
  - It correctly reads loop-dressed instability_modes.npz and does not read raw
    Pvec/Cvec/Dvec.
  - After Level-1 conventions are fixed, use it as downstream Level-2.

TUfRG_realspace_from_modes.py
  - No urgent structural change.
  - It correctly reads loop-dressed modes from Level-1 and does not read raw
    Pvec/Cvec/Dvec.
  - Its current proxy interpretation remains downstream and should only be used
    after the no-SOC bridge test passes.

PACE bridge test after changes
------------------------------

Run no-SOC explicit-spin cases at the same mesh/settings as the old PRR
projected benchmark:
  U=1.5, V=0
  U=0,   V=1.5

Use:
  tu_channel_calc_project = 0
  vertex_convention = official_s1minus1

Optional comparison:
  also run old manual vertex_convention with tu_channel_calc_project=0.

Success criteria:
  U-only:
      leading non-forward channel should be Gamma spin / FM-like.
  V-only:
      leading non-forward channel should be Gamma pp-singlet / onsite-A1 SC-like.
  No SOC:
      ph-sx, ph-sy, ph-sz calibration should be near-degenerate.

If official_s1minus1 passes and manual fails, the vertex convention was the
second major problem.  If both pass, the dominant previous issue was
tu_channel_calc_project=-1.  If neither passes, then inspect PP leg ordering or
PH Pauli projection again.
